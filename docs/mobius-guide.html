换一个 Agent，
不用丢掉走过的路。

Möbius 把分散的会话、项目资料和交接关系放回同一个工作台。你决定从哪里继续，模型自己决定读哪些历史。

01 / DESKTOP

人来组织工作

查看项目与会话、搜索记录、维护文档与画布，在图谱中选中要交接的 session。

02 / CLI

命令明确可查

从终端索引来源、检索、导出祖先图谱；将准备交接与授权启动分开。

03 / MCP + PLUGIN

模型显式调用

让支持 MCP 的客户端查询图谱和来源。读取正文与启动交接需要额外的限定授权。

交接的是引用，不是总结。
只告诉模型记忆经过了哪些 session、原始记录在哪里；不自动总结、压缩或复制整份日志，也不要求模型把所有历史读完。图谱存在，不代表模型已经读过。

02 / CHOOSE YOUR ENTRY POINT

从你习惯的入口开始。

  1. 先找到你的项目与会话

    在工作台选择或添加工程；在会话库的 Sources / 来源中确认原始 session 目录。来源应指向对应 Harness 的记录目录，而不是随便一个代码目录。缺失或未授权的来源需要先处理。

  2. 用内容定位，再看身份

    搜索会话，核对 Harness、原生 ID、时间和工作目录。两个同名会话不一定是同一段工作；不同 worktree 的记录也不应该混为一条历史。

  3. 继续原会话，还是交给另一条新会话？

    Resume original / 继续原会话使用该 Harness 的原生恢复方式。交接则在选定工作目录启动新的目标会话，并携带图谱引用；即使目标 Harness 相同，交接也不等于恢复原会话。

  4. 检查祖先图谱，再确认交接

    项目 → Handoff graph / 交接图。单击查看信息与祖先，双击查看会话；拖动节点只改变视图布局，不修改关系。Shift + 单击或列表复选框选择多个源，审核目标 Harness、worktree 和引用图谱后确认。

  5. 把工作资料留在工作台

    资料库中使用笔记记录文档、用自由画布组织材料。挂载的原始资料保持只读；笔记和画布是工作资料，不会因为放在同一目录就自动进入交接祖先图谱。

本次打开的是隔离演示库。它适合检查新界面和图谱交互，虚构 session 不能作为真实原生恢复验收。正式资料库未因这次展示被迁移。

1. 编译独立工具，选定自己的数据仓库

需要 Git 和可编译本项目的 Rust 工具链。以下是 PowerShell 示例；先编译，再设置路径。仓库尚未发布稳定二进制。

PowerShell / 源码构建
git clone https://github.com/TardisBooo/mobius-connect.git
Set-Location mobius-connect
cargo build --release --locked
$mc = (Resolve-Path .\target\release\mobius-connect.exe).Path
$vault = 'D:\DataVault\MobiusDemo'
& $mc --data-root $vault init
& $mc --data-root $vault doctor

后面的命令都在同一 PowerShell 中执行，复用 $mc 与 $vault。不要把演示 vault 和正式 vault 混用。若需要与桌面共享图谱，必须明确指向桌面实际使用的数据仓库；相同项目路径不会自动共享索引。

2. 授权来源，索引并搜索

PowerShell / 请替换来源目录
# 改为你实际的 Codex sessions 目录
$source = 'D:\YourCodexHome\sessions'
& $mc --data-root $vault sources add codex $source
& $mc --data-root $vault sources refresh
& $mc --data-root $vault sessions list --limit 20
& $mc --data-root $vault sessions search 'retry' --limit 10

从返回结果复制内部 session.id。CLI 的 sessions show/read 与 graph show 接受该 ID，不要用文件名、标题或仅原生 UUID 替代。

3. 查看祖先，按需读取原文

PowerShell / 显式查询
$sid = '从 sessions list 复制的 session.id'
& $mc --data-root $vault sessions show $sid
& $mc --data-root $vault graph show $sid
& $mc --data-root $vault graph export --format mermaid $sid
& $mc --data-root $vault memory reference $sid
& $mc --data-root $vault sessions read $sid --offset 0 --bytes 4096

导出打印到 stdout；支持 JSON、Mermaid 和静态 HTML 引用列表。read 的单位是字节，每次 1–16384 字节；未对齐的 UTF-8 片段可能以 hex 返回，按响应的 encoding 解读。直接 CLI 读取是用户显式操作，MCP 读取则另外要求授权 token。

4. 准备 → 人工授权 → 启动 → 检查状态

PowerShell / 启动会创建新会话
$project = 'E:\Workspaces\demo\app'
$prepared = & $mc --data-root $vault handoff prepare --harness codex --cwd $project $sid | ConvertFrom-Json
$prepared.graph | ConvertTo-Json -Depth 20
$hid = $prepared.handoff.id

# 在你自己的交互终端运行，查看范围后输入 APPROVE
& $mc --data-root $vault approvals handoff $hid

# 从授权结果取出 token；不要发到公开日志或截图中
$token = Read-Host '输入刚才收到的授权 token'
& $mc --data-root $vault handoff commit $hid --approval-token $token
& $mc --data-root $vault sources refresh
& $mc --data-root $vault handoff status $hid
这是一条开发预览流程，不代表全部 Harness 已验收。原生启动当前仅支持 Windows；需要目标 CLI 可用且已由用户配置好认证。一次授权绑定一个不可变交接，默认 5 分钟有效且只能使用一次。unknown 状态不要盲目重试。

1. 先由用户初始化，再连接客户端

完成 CLI 的 init、来源授权和索引。随后在支持 stdio MCP 的客户端中注册服务。下面是常见配置形状，各客户端的配置入口以其实际支持为准；本页面不替你安装或修改配置。

客户端配置示例 / 路径需替换
{
  "mcpServers": {
    "mobius": {
      "command": "E:\\Workspaces\\Mobius\\repos\\mobius-connect\\target\\release\\mobius-connect.exe",
      "args": ["--data-root", "D:\\DataVault\\MobiusDemo", "mcp", "serve"]
    }
  }
}

该服务通过标准输入输出通信，不开放 HTTP 端口。不要把 PowerShell 提示符或普通日志写入 MCP stdout。CLI 和 MCP 使用同一个 vault 才能看到同一份图谱和授权。

2. 从图谱开始，不默认倾倒所有正文

工具用途调用边界
list_sessions / get_index_health列出元数据、检查索引不返回会话正文
get_lineage / resolve_session祖先图谱、已授权原始来源不会自动读原文
build_memory_reference向当前调用方返回图谱引用不启动、不隐式注入
search_sessions / read_session_range检索片段、读取指定字节范围需要限定查询或范围的人工授权
prepare_handoff固化图谱与目标，返回审批请求会写 Möbius 目录，不启动 Harness
commit_handoff / get_handoff_status授权后启动、查询执行状态commit 需要单次 token；状态不是模型理解证明
JSON-RPC / 客户端完成 initialize 后的工具调用
{
  "jsonrpc": "2.0", "id": 2, "method": "tools/call",
  "params": {
    "name": "get_lineage",
    "arguments": { "session_ids": ["替换为真实内部 session.id"] }
  }
}

3. 读取正文，需要独立且精确的授权

例如允许模型读取一个 Codex session 的前 4096 字节：用户保存下面的请求为 range-approval.json，在自己的交互终端执行 & $mc --data-root $vault approvals review .\range-approval.json，审阅后输入 APPROVE。MCP 没有发放 token 的工具。

range-approval.json
{
  "operations": ["read_session_range"],
  "query": "bytes:0:4096",
  "provider": "codex",
  "session_id": "替换为真实内部 session.id",
  "providers": [],
  "max_chars": 8192,
  "expires_in_seconds": 300,
  "single_use": true
}
随后调用 / 参数示例
{
  "name": "read_session_range",
  "arguments": {
    "session_id": "同一个真实内部 session.id",
    "offset": 0,
    "bytes": 4096,
    "approval_token": "用户刚授予的 token"
  }
}

max_chars 为 hex 最坏情况预留 2 × bytes。读取别的范围、别的 session，或发起交接，都需要对应的新授权；不是“一次允许，永久读全库”。

4. 显式插件：把操作习惯交给模型

可选插件位于独立仓库的 plugins/mobius-connect。宿主加载后，显式调用 $mobius-memory：例如“检查我选中会话的祖先，先列出缺失来源，再由我决定是否读取”。它禁用隐式调用、没有注入钩子，不能替你同意授权。插件清单已校验，真实宿主加载仍待验收。

03 / TWO REALISTIC WORKFLOWS

把步骤放进真实工作里。

CASE A / 单条实现链

设计讨论交给实现 Agent

你在 Codex 的 A 中确定重试策略，希望 Claude 接手。桌面选 A → 审核目标目录与引用图谱 → 确认交接。新会话 B 识别后建立 A → B。B 可以按需读 A 的原始记录，而不是只收到一段 Möbius 生成的摘要。

开发能力示范；不同 Harness 的端到端恢复仍须分别验收。

CASE B / 分支汇合

实现与验证，合到下一次交接

Claude 的 B 写实现，Pi 的 C 查故障恢复。选择 B 和 C 作为源：交接图只含 A、B、C，公共祖先 A 去重，不包含同项目的其他对话。目标 D 真正出现并被识别后，才能形成 B → D、C → D。

PowerShell / 多源交接准备
$sidB = 'B 的真实内部 session.id'
$sidC = 'C 的真实内部 session.id'
& $mc --data-root $vault handoff prepare --harness codex --cwd $project $sidB $sidC
# 检查返回图谱后，再按前面的人工授权 → commit → status 流程继续。

状态如何解读？

preparedstartingawaiting_identitybound

已准备 → 正在启动 → 等待识别目标 → 已绑定目标 session。bound 也不代表模型读取或理解了全部历史。failed / cancelled / unknown 需要检查原因；不要靠反复点击制造重复会话。桌面与独立 CLI 的状态展示并非完全一致，上面是独立工具的生命周期。

04 / KNOW THE BOUNDARY

知道它做了什么，也知道没做什么。

能力当前状态
祖先回溯、多源合并、来源权限、节点别名核心测试及桌面 WebView 回归通过；演示数据与真实 Harness 验收分开统计。
大 session 引用约 1.22 GB 的真实源日志生成 758 字节图谱；该次未复制日志，也未要求全文读取。这不是通用性能保证。
搜索桌面提供会话检索及相关记忆入口；独立 CLI/MCP 当前仅暴露 lexical 检索，不能当作已完成的语义检索 API。
官方 Codex 恢复真实新建对话在 app-server 重启后恢复通过；不能替代外部 TUI /resume、跨 Harness 交接验收。
CLI/MCP 与插件独立构建与基础协议/权限测试通过，插件结构通过校验；插件宿主加载及真实启动闭环仍待验收。
发布状态开发预览，未发布稳定新版。Pi/Grok 真实交接恢复、目标身份确认加强和安装包生命周期仍在待办中。
为什么同一目录里的另一个会话没有被继承？

目录用于组织项目，不用于推断交接关系。只有明确记录的 session 边属于祖先路径。需要结合另一段工作时，显式选择多源交接，而不是默认把整个项目历史塞进去。

找不到原始来源，或准备交接失败怎么办？

先检查 Sources 的授权目录、文件是否仍存在、session ID 是否来自同一个 vault，以及目标 checkout 是否已注册。图谱中的缺失来源会明确标出；不要通过修改 Harness 的历史 JSONL 来“修复”路径。

图谱能让模型自动知道全部过去吗？

不能。它提供路标和来源。模型是否读取、读取多少、如何使用，由模型及其 Harness 决定。原始历史里的命令也只是历史数据，不是新的执行授权。
